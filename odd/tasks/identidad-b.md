# Identidad B · Semáforo sereno

Restyle the authenticated product to identity direction B (`design/identidad-gastos/02,05-08`) plus UX improvements that reuse the current API.
Worktree `../gastoscontrolados-identidad`, branch `feat/identidad-b` from `main` 8e5fb82. Baseline: `npm run build && npm test` → 385/385 pass.

## Specs

- **S1 — No loss.** "el sitio no debe perder funcionalidad, ni visualizacion de la informacion". Every panel, action and piece of information in the current inventory stays reachable and visible: app header (Gmail conectado badge, account menu with Configuración and Cerrar sesión), dashboard header (greeting, title, period context, period button, Actualizar, Nuevo gasto), lead (total gastado, saldo disponible, % del ingreso disponible, Al límite / En peligro), budget panel (income, budget card), Distribución de gastos, spending chart (tabs, bars, summary, day panel, note), Dónde se fue tu plata (donut, legend, detail), Top Comercios y Personas, insights, financial warning, feedback notices, all dialogs; movements view (header, 4 metrics, pending note, filters, kind tabs, active filters, bulk actions, mobile list, table with Ver/Editar/Eliminar); demo view (read-only badge, footer); loading, failed and unconfigured states. New elements are additive or a restyle of the same element.
- **S2 — Identity.** Direction B "Semáforo sereno": state colors en ritmo `#0b7a6b` (soft `#e2f3ef`), ajustado `#9a6700` (soft `#fdf3d8`), pasado `#b4412f` (soft `#fbe9e5`), track `#efeee9`; keep canvas `#f6f5f2` and ink `#131b2e`. Logo = the month gauge mark (ring + "today" tick), used in the app header, landing header/footer and as favicon. `index.html` gains favicon, meta description, Open Graph/Twitter title+description and a web manifest. Existing tokens stay (tests pin them); new tokens are added.
- **S3 — Month gauge.** The summary shows the gauge from artboard 02/08: "Te quedan" + remaining amount, "$X por día" for the days left, % of income spent vs % of cycle elapsed (ring + tick), a state with word and icon — "En ritmo", "Ajustado", "Pasado" — and a sentence "Llevas N% del ingreso y pasó el M% del ciclo. Si sigues así, cierras con unos $X de sobra." (or "…terminas unos $X bajo cero."). Rules: elapsed = days elapsed including today / cycle days (0 before start, 1 after end); spent = totalSpending / income; Pasado when remaining < 0 or spent > elapsed + 0.10; Ajustado when spent > elapsed; else En ritmo; projection = totalSpending / elapsed. Without income: no state, and an action to add the income. Works in the demo.
- **S4 — Mobile navigation.** On narrow screens the view navigation becomes a bottom bar (Resumen, Movimientos) with a central "Agregar gasto" button that opens the same manual-expense dialog; hidden in the demo where creation is disabled. Desktop keeps the top header restyled.
- **S5 — States.** Empty summary offers actions ("Agregar gasto", "Actualizar") next to the existing copy; loading keeps the skeleton; failed state says data already saved is safe and keeps "Reintentar resumen financiero".
- **S6 — Manual expense.** Amount first, large, `inputmode="numeric"`, thousands formatting while typing; date defaults to now when inside the period; jargon "Catálogo de solo lectura" replaced by plain copy. All fields and validation stay.
- **S7 — Recategorize with rule + undo.** When changing a movement's category, an option "Usar siempre para <comercio>" saves a counterparty rule in the same step; the confirmation offers "Deshacer", which restores the previous category and the previous rule state.
- **S8 — Onboarding.** Step 1 (unauthenticated): trust in 3 points — "Qué leemos", "Qué nunca hacemos", "Cómo salir" — plus a link to the demo. Step 2 (cycle setup): presets "Mes calendario" and "Desde mi día de pago" that fill the existing date inputs; calendar and inputs stay. Step 3: after the first cycle setup, a dismissible explanation of how to read the gauge.
- **S9 — Honest consent.** Consent copy states that Google grants read access to the whole Gmail and the app filters Banco de Chile mails; data the user applies is stored on the server tied to the account (not "localmente"); no mention of a monthly budget that does not exist.
- **S10 — No backend.** "Lo anterior + mejoras de UX sin backend": no server, schema or API changes; only existing endpoints.
- **S11 — Summary polish (artboard 01).** "recomienda mejoras para que parezca un producto terminado, intuitivo con una linea grafica marcada, sencillo de entender, con buenas animaciones" — implement `design/identidad-b-pulido/01-resumen-desktop-protagonista.html` (primary checkout) in the real stack: the month gauge is a full-width hero whose number is the largest on screen (48px desktop, 44px mobile) and that contains income / spent / remaining / % once (the duplicated KPI band merges into it); the "Presupuesto · No configurado" card is removed; one state vocabulary "En ritmo" / "Ajustado" / "Vas rápido" replaces "Al límite / En peligro" and "Pasado"; no residual cobalt in the summary (actions in ink, state hues only for month state, ajustado `#8f5f00`); categories use a muted categorical palette that never reuses state hues; type scale 28 title / 18 section / 15–16 body / 12 minimum; gauge ring sweep + count-up 700ms, pill fade after the ring, all off under `prefers-reduced-motion`. Every other S1 panel stays, in order; the demo keeps "Datos de ejemplo · Solo lectura". No backend (S10).
- **S12 — Mobile summary (artboard 03).** Implement `design/identidad-b-pulido/03-resumen-mobile.html`: bottom bar Resumen · Agregar gasto (central) · Movimientos with the active item shown by a filled pill and color (not only weight) and `aria-current="page"`; in the demo, where creation is disabled, no empty gap is left; content padding so the bar never covers the last item; the "Deshacer" notice auto-dismisses after 7 s with a shrinking timer bar (no bar and no auto-dismiss timer animation under reduced motion, still dismisses).
- **S13 — Onboarding (artboards 04, 05).** Implement `design/identidad-b-pulido/04-onboarding-desktop.html` and `05-onboarding-mobile.html` in `OnboardingConnect`: desktop two columns (left logo, "Paso 1 de 3 · Conectar", headline, subtitle, "Conectar Gmail" in ink with an inline Google "G", "Ver la demo"; right the three trust points and a small example gauge), named steps "1 Conectar · 2 Tu ciclo · 3 Tu medidor", h1 larger than h2, body 16px; mobile single column with "Conectar Gmail" above the fold. Same consent copy (S9) and the real connect control.
- **S14 — Summary layout cleanup.** Insights move to a full-width row below the panels as in artboard 01 (no gap under the left column on desktop); the unmounted `DashboardLeadView` and `DashboardBudgetPanel` (and their CSS/tests that only exist for them) are removed.
- **S15 — Motion (phase 2).** "con buenas animaciones": switching Resumen ↔ Movimientos crossfades the content (300ms, no layout jump, focus and scroll position behave as today); at ≤760px dialogs open as bottom sheets that slide up and slide down on close (300ms), desktop dialogs fade/scale in (150ms); feedback notices slide in (300ms); after a movement edit is saved, its row in the movements table/list highlights briefly (~1.2s fade). Durations use the motion tokens (150 routine / 300 view change / 700 gauge). Under `prefers-reduced-motion` every one of these is an immediate state change with the same information.
- **S16 — Landing (phase 3).** The landing uses the brand line: the phone/dashboard previews show the month gauge instead of the old lead band ("Al límite / En peligro"), the primary CTAs use ink, and no residual cobalt remains on the landing; the old `DashboardLeadView` is then removed. Copy, sections, anchors, sign-in and tour behavior stay (S1).
- **S17 — Demo scenarios (phase 3).** The demo offers "Ver la demo como: En ritmo · Ajustado · Vas rápido", which simulates the day of the cycle (the same demo data read on a later or earlier day) so the gauge, sentence and state change consistently; it opens on "Ajustado" so the first impression is not alarming; the control is clearly part of the demo (next to "Datos de ejemplo · Solo lectura"), keyboard accessible, and absent from the authenticated app.
- **S18 — Movements view polish.** The movements view gets the same brand line as the summary (artboards `design/identidad-b-pulido/06-movimientos-desktop.html` and `07-movimientos-mobile.html`, based on the accepted `design/identidad-gastos/05-b-movimientos.html`): no cobalt (ink for tabs and actions), category chips use the same color as that category in the donut, type scale 28/18/15–16/12; the 4 metrics stay with clear hierarchy, "Sin categoría" becomes an actionable prompt ("N movimiento(s) sin categoría") that filters to them; table and mobile list more legible (amount right-aligned and stronger, short dates like "2 nov", more row spacing); active filters visible with a "Limpiar filtros" action; "sin resultados" shows the active filters and a way to clear them; empty state with a clear action. Every existing function stays (S1): search, category filter, kind tabs, active filters, bulk actions, pending note, mobile list, table sorting, Ver/Editar/Eliminar, demo read-only note.
- **S19 — Remaining dialogs close motion.** The dialogs that still unmount abruptly (edit and remove movement, account settings, category settings, counterparty rules, Gmail consent, complete cycle, edit cycle) animate out like the rest (≤760px sheet slides down 300ms, desktop fade/scale 150ms, immediate under reduced motion), reusing `useRetainedWhileClosing`; behavior, validation, focus return and tests unchanged.
- **S20 — Cycle setup made intuitive.** "mejora ese modal, esta desordenado, tiene mucha info enredada.. haz que sea mucho mas intuitivo, me gustan las primeras opciones de Mes del calendario, desde mi dia de pago y otro rango, pero que sea mas entendible." The first-cycle setup (and the edit-period dialog with the same structure) asks one question, "¿Cuándo empieza tu mes?", with the three options Mes calendario / Desde mi día de pago / Otro rango; each option reveals only what it needs (calendar month: nothing to fill, a clear result line; pay day: one "¿Qué día te pagan?" choice and the resulting range; other range: the calendar and the start/end date inputs, which stay available there — this refines S8's "calendar and inputs stay"); the optional income is a separate, explained field ("Lo usamos para tu medidor"); a persistent summary of the chosen period and one clear primary action. Validation, saved data and API calls unchanged (S10).
